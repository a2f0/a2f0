# Repository guidance

This is the a2f0 GitHub profile repository. GitHub would show a root
`README.md` on the public profile, which the owner leaves at GitHub's default,
so the repository has no README; never add one. Development material lives in
[docs/development.md](docs/development.md). Resolve GitHub identity with
`gh repo view --json nameWithOwner`. Work on a feature branch created with
`agent-tool branch create <type>/<topic> --base main --remote origin`, preserve
unrelated edits, and use signed Conventional Commits without co-author
trailers. Do not force-push or add attribution footers.

## Setup and validation

Bun and ShellCheck are pinned in `.mise.toml`, with URLs and checksums
committed in `mise.lock`; regenerate it with `mise lock` whenever `.mise.toml`
changes. CI's `jdx/mise-action` `version` must read the lockfile format (format
4 needs mise 2026.11.1+), so move those pins before the lock's format. In agent
shells, put the matching directories under `~/.local/share/mise/installs`
first on `PATH` in each command, after any `cd`, rather than running
`mise trust`. Install with `bun install --frozen-lockfile`, then run
`bun run hooks:install`; run it again after returning to `main` from a merge.

Run `bun run check` for Biome, the type checker, the tests, the site build,
ShellCheck over the hooks, the binary-file check, and the managed skill and
permission checks. Biome also rejects import cycles, counting type-only
imports. The modules without imports are `src/history.ts`, `src/web.ts`,
`src/theme.ts`, and `src/pageLogic.ts`; `src/grid.ts` builds on the history
and the page logic, `src/site.ts` on every other module, and the scripts on
top. The page embeds every function in `src/pageLogic.ts` by its source, so
each may use only its parameters, built-ins, and the other functions there.

`contributions/commits.json` is written only by the matrix workspace's
`bun run contributions`; never edit it by hand. Its format is in
[docs/development.md](docs/development.md#updating-the-counts).

The contributions grid is a web page at <https://a2f0.github.io/a2f0/>,
rendered from that file by `bun run site:build` into the ignored `dist/site`,
and CI deploys it from `main` after the `CI gate`. Its icons and preview
image are rendered from `assets/brand/logo.svg` by `agent-tool images build`,
as `agent-tool.json` declares; never commit them. Check a page change in a
browser with `bun run site:dev`, started through `agent-tool proc start`, at
desktop and phone widths in both themes.
[docs/development.md](docs/development.md#web-page) describes it.

The hooks in `scripts/git/hooks` are installed by agent-tool from
`agent-tool.json`: `commit-msg` checks subject and attribution policy, and
`pre-commit` checks the branch name and staged binaries. `pre-push` is
agent-tool's push gate, generated by `agent-tool push-gate hook`; do not edit
it. It runs the shared guards (hook freshness, managed skills and permissions,
destination branch names, commit signatures and subjects, binaries) on the
pushed commits, then the static steps in `agent-tool.json`'s `pushGate`: Biome,
the type checker, and ShellCheck. Tests never run on push; CI runs them, and
when a CI job fails, push a reviewed fix to the same branch.

## Output capture

Run Bun tests through `bun run agent-tool bun test --log [-- args...]`, and
other finite, noisy commands, such as installs, builds, linters, package
scripts, and Git commands that run hooks, through
`bun run agent:run --label <name> -- <command> [args...]`. Each keeps complete
output in a private log, preserves the exit status, and prints a compact
receipt, with a bounded excerpt of the log on failure. Read more with
`bun run agent:logs <log-path>`, raising `--tail-lines` or `--max-bytes` as
needed, or with a targeted search of the log. A zero exit does not rule out
warnings: inspect required warnings, timings, and artifacts before accepting a
check. Run reviews, version preparation, audits, infrastructure previews, and
run-group checks directly so their results stay visible, and run interactive
tools and servers directly too. Never narrow a suite or silence warnings to
reduce output.

For example, capture a push with
`bun run agent:run --label push -- bun run agent-tool branch push <head> --remote origin`;
the push log holds the push gate's receipt, and `bun run agent-tool runs list`
lists its step timings. `bun run check` is already an `agent-tool run-group`
that records each step, so run it directly.

## State machines

Make implicit state machines explicit when you write or change code: one closed
state type (a discriminated union, enum, or sealed type) carrying each state's
data, typed events, and one pure transition function, with effects run on
entering a state and async work tagged so only the current request can finish.
Follow the `explicit-state-machines` skill for what to convert, what to leave
alone, and how to prove behavior did not change; `agent-tool state-machines`
lists leads. Reviews flag new implicit machines.

Here a closed state type is a TypeScript discriminated union on a `kind` field,
with its transition function beside it. The site renderer is a pure function
from the counts file to files; the web page's tooltip is the one machine,
`nextTooltip` in `src/pageLogic.ts`, which every pointer, focus, and key
listener in the page script feeds. The repository toggles keep no state of
their own: each change redraws every view from the checkboxes through
`shadeDays`.

## Shared skills and shipping

`@a2f0/agent-tool` is pinned exactly in `package.json` and `bun.lock`. After
updating it, run `bun run agents:sync` and commit the lockfile,
`.agent-tool-skills.json`, `.agent-tool-permissions.json`, the generated skills
under `.agents/skills` and `.claude/skills`, and the permission rules in
`.claude/settings.json`, `.codex/rules/`, and `.gemini/policies/` together. Do
not edit managed skills or generated rules. Keep repository guidance here; do
not add CLAUDE.md, GEMINI.md, or other files under `.gemini/`.

Use the installed `ship-pr` skill for authorized shipping, including an
independent review of the committed HEAD. Changes land on `main` as
squash-merged pull requests, the only merge method the repository allows.
`main` has no branch protection or ruleset, so `agent-tool pr merge` is the
gate: the required check is `CI gate` from workflow `CI`, which passes only
when the `lint`, `test`, and `site` jobs succeed
(`scripts/checks/ci-gate.json`). A branch need not be current with `main` to
merge (`merge.requireStrictBaseFreshness` is false); integrate `main` only
when GitHub reports a conflict. CI runs on every push to `main`, and `ship-pr`
starts from `agent-tool repo base-health`, repairing a red `main` before or
alongside the requested change. Merging publishes the web page to GitHub Pages
through the `Deploy` job; after a merge, check the live page with
`agent-tool seo probe a2f0.github.io /a2f0/`.
